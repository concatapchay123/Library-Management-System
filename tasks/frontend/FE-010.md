# FE-010 — Public membership, fine, payment and invoice views

## Task information

- Owner: Frontend
- Status: Completed
- Priority: P2

## Outcome

Present public-library membership and financial records in clear, non-technical views while leaving payment security and state decisions to the backend.

## Dependencies

- FE-009

## Interfaces and source of truth

- Consumes: membership endpoints from BE-022, financial records from BE-023 and payment state from BE-024.
- Produces: public-library routes for memberships, fines, payments and invoices.

## In scope

- Render current membership/subscription status and server-provided borrowing policy summary.
- Show fine, payment and invoice history with explicit currency, status and immutable issued totals.
- Display pending, failed, settled, partial and refund state in plain language using backend data.

## Out of scope

- Card collection, provider signature handling, money calculation, browser storage of payment data and client-side settlement.

## Test-first sequence

1. Add frontend/tests/features/public-library/public-library-workspace.test.tsx for membership summary, pending payment, invoice detail and safe error state.
2. Run: cd frontend; npm run test -- --run tests/features/public-library/public-library-workspace.test.tsx. Record the missing public-library-screen failure.
3. Implement membership and financial record routes through the typed client.
4. Run the focused test, npm run typecheck, npm run lint and npm run build.

## Acceptance criteria

- [x] Financial status uses text and non-color cues (`● Active`, `⊘ Suspended`, `⏱ Pending`, `✓ Settled`, `✕ Failed`, `— Waived`, `↺ Refunded`, `◒ Partial Refund`).
- [x] Issued invoice totals are read-only (`<Input readOnly />`, immutable amount badges, no client line manipulation controls).
- [x] Payment information never includes card data, provider secrets (`whsec_`, `secret_key`), or raw webhook materials.

## Reviewer checklist

- [x] UI does not infer payment success from an HTTP retry alone; status transitions strictly depend on authoritative backend `/reconcile` responses.
- [x] Financial controls expose only backend-authorized actions (backend `/fines/{id}/waive`, `/invoices/{id}/void`, `/payments/{id}/reconcile`).
- [x] Safe 403 `edition-unavailable` state renders with zero tenant connection leaks and accessible navigation path back to Circulation Desk (`#/circulation`).
