# FE-003 — Login, refresh session and protected-route behavior

## Task information

- Owner: Frontend
- Status: Completed
- Priority: P2

## Outcome

Let users authenticate with organization slug and manage browser session recovery without persistent access-token storage.

## Dependencies

- FE-002

## Interfaces and source of truth

- Consumes: auth endpoints in contracts/openapi/v1.yaml and shared controls from FE-002.
- Produces: login form, in-memory access-token state, refresh flow and protected-route guard.

## In scope

- Implement organization_slug, email and password login fields in familiar order.
- Keep access tokens only in memory and use the HttpOnly refresh cookie through the documented refresh endpoint.
- Redirect protected routes after session failure and display the uniform safe authentication message.

## Out of scope

- Password-reset UI, role management, localStorage/sessionStorage token persistence and client-side permission enforcement.
