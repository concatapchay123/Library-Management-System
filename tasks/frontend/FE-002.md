# FE-002 — App shell, familiar navigation and accessible shared controls

## Task information

- Owner: Frontend
- Status: Planned
- Priority: P2

## Outcome

Provide a simple application shell with familiar navigation and reusable accessible controls for low-tech users.

## Dependencies

- FE-001

## Interfaces and source of truth

- Consumes: PRODUCT.md, DESIGN.md and frontend tokens from FE-001.
- Produces: app layout, navigation model, button/input/dialog primitives and responsive focus behavior.

## In scope

- Add logo-to-home navigation, primary navigation, page heading region and account area.
- Build accessible button, labeled input, status message and dialog controls with Escape dismissal.
- Limit each screen region to one visually primary action and group related fields with token spacing.

## Out of scope

- Authentication, API state, catalog content, visual effects and custom design-system expansion.

## Test-first sequence

1. Add frontend/tests/app/shell.test.tsx for landmark order, logo home link, keyboard navigation and Escape dialog close.
2. Run: cd frontend; npm run test -- --run tests/app/shell.test.tsx. Record the missing shell failure.
3. Implement shell, navigation and shared controls.
4. Run the focused test, npm run typecheck, npm run lint and npm run build.

## Evidence checkpoint

- Keyboard traversal reaches navigation and the main action in a predictable order.
- Dialog controls close with Escape and return focus to the trigger.

## Acceptance criteria

- Navigation labels use product language rather than technical identifiers.
- Shared controls expose labels, descriptions and validation messages programmatically.
- Layout remains usable at narrow viewport widths without hiding primary actions.

## Reviewer checklist

- One screen region does not contain competing primary buttons.
- No authorization decision is inferred from navigation visibility.
