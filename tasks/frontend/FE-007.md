# FE-007 — Circulation desk for request, approval, checkout and return

## Task information

- Owner: Frontend
- Status: Planned
- Priority: P2

## Outcome

Let authorized staff complete the core circulation lifecycle through a clear, low-step desk workflow.

## Dependencies

- FE-006

## Interfaces and source of truth

- Consumes: loan endpoints from BE-016 and idempotency behavior from BE-017.
- Produces: circulation route, request/approval/checkout/return actions and operation-result view.

## In scope

- Present current loan state and only the next server-permitted action.
- Support self-service request and staff approval/checkout/return flows.
- Handle repeat submission, conflict and domain failures through typed API responses.

## Out of scope

- Reservation queue management, money collection, policy calculation and multiple competing lifecycle actions.

## Test-first sequence

1. Add frontend/tests/features/circulation/circulation-desk.test.tsx for request, approval, checkout conflict and return success.
2. Run: cd frontend; npm run test -- --run tests/features/circulation/circulation-desk.test.tsx. Record the missing circulation-screen failure.
3. Implement lifecycle views and typed mutation actions.
4. Run the focused test, npm run typecheck, npm run lint and npm run build.

## Evidence checkpoint

- A checkout conflict preserves the displayed state and explains the next safe action.
- Repeat click behavior does not create a second visible completed operation.

## Acceptance criteria

- One lifecycle action is visually primary at a time.
- User language distinguishes request, approval, checkout and return.
- The UI does not calculate eligibility, due date or copy locking.

## Reviewer checklist

- Idempotency keys and request replay are handled only through the documented client contract.
- The desk UI does not bypass server authorization or workflow state.
