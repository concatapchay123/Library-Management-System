# FE-005 — Catalog search and book browsing

## Task information

- Owner: Frontend
- Status: Planned
- Priority: P2

## Outcome

Enable users to find and inspect bibliographic books through a simple, typed catalog experience.

## Dependencies

- FE-004

## Interfaces and source of truth

- Consumes: book endpoints and cursor rules from BE-012 and the typed client from FE-004.
- Produces: catalog search route, book list, book detail and cursor-pagination controls.

## In scope

- Add one prominent search action with documented supported filter inputs.
- Render clear result summaries, empty state, loading state and recoverable error state.
- Add book detail views without exposing data from unavailable editions or tenant boundaries.

## Out of scope

- Copy mutation, inventory status changes, client-side search SQL, recommendation features and advanced saved search.

## Test-first sequence

1. Add frontend/tests/features/catalog/catalog-search.test.tsx for query submit, empty result, cursor continuation and API error rendering.
2. Run: cd frontend; npm run test -- --run tests/features/catalog/catalog-search.test.tsx. Record the missing catalog-screen failure.
3. Implement catalog routes and typed client integration.
4. Run the focused test, npm run typecheck, npm run lint and npm run build.

## Evidence checkpoint

- Search results explain when no matching books are available.
- Cursor continuation preserves the selected supported filter.

## Acceptance criteria

- The screen distinguishes bibliographic books from physical copies in user language.
- The primary action is search; secondary controls do not compete visually.
- Keyboard users can submit a search and inspect results without pointer-only interactions.

## Reviewer checklist

- UI does not promise copy availability beyond API data.
- Feature code contains no direct database or authorization access.
