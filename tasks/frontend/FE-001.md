# FE-001 — Frontend bootstrap, product UI context, tokens and test tooling

## Task information

- Owner: Frontend
- Status: Planned
- Priority: P2

## Outcome

Create the React/TypeScript workspace, durable product UI context, foundational tokens and deterministic frontend checks.

## Dependencies

- BE-026

## Interfaces and source of truth

- Consumes: DESIGN.md, docs/architecture.md and the complete OpenAPI contract.
- Produces: frontend package, PRODUCT.md, application token layer and frontend test/type/lint/build commands.

## In scope

- Initialize React, TypeScript, test runner, type-check, lint and production-build scripts.
- Record an Operate-mode product UI brief in PRODUCT.md derived only from DESIGN.md.
- Define spacing, typography, color and focus tokens for a low-tech, accessible operating interface.

## Out of scope

- App navigation, login screen, API calls, feature screens and visual rebranding.

## Test-first sequence

1. Add frontend/tests/app/bootstrap.test.tsx that imports the root application and token provider.
2. Run: cd frontend; npm run test -- --run tests/app/bootstrap.test.tsx. Record the missing workspace failure.
3. Implement the smallest frontend bootstrap, product context and token layer.
4. Run the focused test, npm run typecheck, npm run lint and npm run build.

## Evidence checkpoint

- Frontend test, type-check, lint and build commands are documented and pass.
- PRODUCT.md states audience, operating mode and the minimum-comprehension UI rule.

## Acceptance criteria

- Tokens use a consistent spacing scale and visible keyboard focus.
- The application can render without a network request.
- PRODUCT.md does not invent product scope beyond DESIGN.md.

## Reviewer checklist

- No business rules or API endpoint strings are embedded in token code.
- Tokens support readable contrast and non-color status cues.
