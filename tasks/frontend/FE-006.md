# FE-006 — Inventory, locations, copies and status-management workspace

## Task information

- Owner: Frontend
- Status: Planned
- Priority: P2

## Outcome

Give authorized librarians one focused workspace to register copies, assign locations and make server-validated inventory status changes.

## Dependencies

- FE-005

## Interfaces and source of truth

- Consumes: location/copy endpoints from BE-013 and status endpoint from BE-014.
- Produces: inventory route, copy form, location assignment controls and status-history view.

## In scope

- Add copy creation and location assignment forms with labels and immediate client validation.
- Render permitted server-defined status actions and immutable status history.
- Surface stable Problem Details beside the relevant form field or action.

## Out of scope

- Inventing status transitions, bulk import, checkout/return workflow and browser-side tenant selection.

## Test-first sequence

1. Add frontend/tests/features/inventory/inventory-workspace.test.tsx for copy registration, status failure and history display.
2. Run: cd frontend; npm run test -- --run tests/features/inventory/inventory-workspace.test.tsx. Record the missing inventory-workspace failure.
3. Implement typed forms, status controls and history rendering.
4. Run the focused test, npm run typecheck, npm run lint and npm run build.

## Evidence checkpoint

- Invalid server transition displays a comprehensible message without changing local history.
- History is visibly read-only and identifies actor, reason and time.

## Acceptance criteria

- Barcode, location and condition fields have explicit labels and help text.
- One primary form submission exists per workflow panel.
- The UI shows only status actions returned or permitted by the backend.

## Reviewer checklist

- Client validation improves feedback but never substitutes backend validation.
- No copy-level state is rendered as a book-level fact.
