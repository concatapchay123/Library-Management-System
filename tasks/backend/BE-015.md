# BE-015 — Durable dispatcher, job records, lease, retry and deduplication

## Task information

- Owner: Backend
- Status: Planned
- Priority: P1

## Outcome

Deliver the generic worker protocol that safely claims durable outbox events and records bounded, replay-safe processing.

## Dependencies

- BE-005

## Interfaces and source of truth

- Consumes: ops.outbox_events from BE-005 and worker rules in docs/system-design.md.
- Produces: ops.job_records, ops.claim_outbox_event, dispatcher service, lease protocol and consumer-deduplication port.

## In scope

- Migrate job records and claim metadata.
- Atomically claim one event with a lease and server-derived organization context.
- Implement bounded retry, dead-letter state, lease reclamation and idempotent consumer recording.

## Out of scope

- Domain-specific reservation logic, email provider integration and notification persistence.

## Test-first sequence

1. Add backend/tests/integration/ops/test_dispatcher.py for single claim, crash/reclaim, dead-letter and duplicate delivery.
2. Run: cd backend; python -m pytest tests/integration/ops/test_dispatcher.py -q. Record the absent-dispatcher failure.
3. Implement migrations, claim procedure, dispatcher and consumer-deduplication port.
4. Run the focused integration test against SQL Server and Redis.

## Evidence checkpoint

- A worker crash after claim does not lose an event.
- Replayed delivery does not execute a consumer side effect twice.

## Acceptance criteria

- Consumer code receives tenant context only from the server-created event record.
- Retries are bounded and exhausted events are visible in a dead-letter state.
- Event payload version is checked before consumer handling.

## Reviewer checklist

- No worker accepts a client-selected tenant id.
- Lease expiry cannot silently skip an event.
