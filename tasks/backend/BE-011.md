# BE-011 — Tenant middleware, pool cleanup, organization settings and RLS catalog enforcement

## Task information

- Owner: Backend
- Status: Planned
- Priority: P0

## Outcome

Set authenticated tenant context safely for every request and prove tenant protections remain complete as tables are added.

## Dependencies

- BE-004
- BE-010

## Interfaces and source of truth

- Consumes: verified principal from BE-008, shared predicate from BE-004 and tenant rules in docs/database-design.md.
- Produces: transaction-scoped SESSION_CONTEXT middleware, organization settings API, bootstrap command and catalog verifier.

## In scope

- Set organization context before the first protected query and clear it before connection-pool release.
- Invalidate a connection when cleanup fails.
- Add privileged organization bootstrap and authorized organization-settings operations.
- Validate that every tenant table has organization_id, composite tenant relations and filter/block RLS predicates.

## Out of scope

- Public organization administration, cross-tenant user APIs and new business-domain tables.

## Test-first sequence

1. Add backend/tests/integration/tenancy/test_tenant_context.py for cross-tenant read/write denial, pool reuse and policy-free fixture detection.
2. Run: cd backend; python -m pytest tests/integration/tenancy/test_tenant_context.py -q. Record the missing middleware/catalog failure.
3. Implement context lifecycle, catalog verifier, settings use case and bootstrap command.
4. Run the focused integration suite against SQL Server.

## Evidence checkpoint

- Tenant A followed by Tenant B on a pooled connection cannot retain A context.
- A deliberately policy-free tenant fixture fails the catalog check.

## Acceptance criteria

- Missing tenant context fails closed.
- SQL Server blocks cross-tenant SELECT, INSERT, UPDATE and DELETE.
- Bootstrap is not reachable through an ordinary tenant-user API.

## Reviewer checklist

- Cleanup failure invalidates the physical connection.
- Catalog rules verify both RLS predicates and composite tenant foreign keys.
