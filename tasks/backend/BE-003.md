# BE-003 — SQL Server migration baseline and database identities

## Task information

- Owner: Backend
- Status: Completed
- Priority: P0

## Outcome

Establish the migration baseline and enforce distinct least-privilege migration and runtime database identities.

## Dependencies

- BE-002

## Interfaces and source of truth

- Consumes: docs/database-design.md, docs/security.md and Compose services from BE-002.
- Produces: migration command, runtime connection contract and SQL Server role-grant verification.

## In scope

- Add the migration runner and clean-database bootstrap path.
- Create migration and runtime identities with distinct grants.
- Verify the runtime identity cannot run DDL or alter RLS policies.

## Out of scope

- Tenant-owned business tables, tenant resolver logic and user-facing database APIs.

## Test-first sequence

1. Add backend/tests/integration/migrations/test_database_roles.py for clean migration and denied runtime DDL.
2. Run: cd backend; python -m pytest tests/integration/migrations/test_database_roles.py -q. Record the missing migration-role failure.
3. Implement migration configuration, database roles and grant verification.
4. Run the focused integration test against SQL Server.

## Acceptance criteria

- Migration and runtime credentials are separate configuration values.
- Runtime is not db_owner and lacks DDL, CONTROL, IMPERSONATE and RLS-policy alteration grants.
- Migration execution is reproducible from the documented command.
