## Evidence checkpoint

- Re-running one due job does not duplicate state changes or outbox events:
  Verified via `test_repeat_overdue_evaluation_does_not_duplicate_state_or_events` in `tests/unit/core/test_overdue_jobs.py` and `test_repeat_scheduled_overdue_evaluation_job_idempotent` in `tests/integration/core/test_overdue_jobs.py`. After the initial evaluation transitioned due loans to `overdue` and emitted outbox events, a subsequent run with the same `as_of` found 0 due loans, emitted 0 duplicate outbox events or audit records, and when executed as a scheduled worker job, was deduplicated via `ConsumerDeduplicationPort` / `ops.processed_jobs`.
- Worker execution receives tenant context from persisted work only:
  Verified via `test_tenant_isolation_in_overdue_evaluation` and `test_scheduled_overdue_evaluation_dispatcher_job` in `tests/unit/core/test_overdue_jobs.py` as well as `test_scheduled_overdue_evaluation_tenant_isolation` in `tests/integration/core/test_overdue_jobs.py`. The claimed event carries `organization_id` in its aggregate/payload, and handler sets up tenant context scoped exclusively to that `organization_id`. Loans or reservations belonging to other tenants are untouched.

## Acceptance criteria

- Overdue state is calculated from stored loan facts, not an email outcome:
  Evaluator queries `core.loans` directly for `organization_id = :organization_id AND status = 'checked_out' AND due_at IS NOT NULL AND due_at < :as_of`, completely decoupled from any email outcome or notification service.
- Job failures use bounded retry and dead-letter visibility:
  Integrated directly into the generic `OutboxDispatcherService` worker contract (`ops.outbox_events`, `ops.processed_jobs`), adhering to bounded attempts, leases (`lease_token`, `lease_expires_at`), retry backoff, and dead-letter status tracking.
- Scheduled work is observable through job records:
  Every run records a completed or failed job entry via `ConsumerDeduplicationPort.record_job_status` / `record_processed` and emits an audited outbox event `circulation.loan_overdue`.
