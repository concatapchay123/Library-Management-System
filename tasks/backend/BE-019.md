# BE-019 — Overdue calculation and scheduled circulation jobs

## Task information

- Owner: Backend
- Status: Planned
- Priority: P1

## Outcome

Calculate overdue loan state and execute scheduled circulation work through the generic worker contract.

## Dependencies

- BE-018
- BE-015

## Interfaces and source of truth

- Consumes: loan state from BE-016, reservation events from BE-018 and job protocol from BE-015.
- Produces: overdue evaluator, scheduled job registration and overdue outbox events.

## In scope

- Define overdue transition rules based on stored due dates.
- Register durable scheduled work for overdue evaluation and hold-expiry processing.
- Keep scheduled workers independent from email and UI delivery.

## Out of scope

- Fine calculation, email templates, payment collection and frontend notifications.

## Test-first sequence

1. Add backend/tests/integration/core/test_overdue_jobs.py for due-date transition, tenant isolation and repeat job execution.
2. Run: cd backend; python -m pytest tests/integration/core/test_overdue_jobs.py -q. Record the missing scheduled-job failure.
3. Implement overdue evaluator and scheduled dispatcher registrations.
4. Run the focused integration test and dispatcher test.

## Evidence checkpoint

- Re-running one due job does not duplicate state changes or outbox events.
- Worker execution receives tenant context from persisted work only.

## Acceptance criteria

- Overdue state is calculated from stored loan facts, not an email outcome.
- Job failures use bounded retry and dead-letter visibility.
- Scheduled work is observable through job records.

## Reviewer checklist

- Clock use is injectable in tests.
- No task performs cross-tenant scanning through a runtime tenant identity.
