# BE-007 — Argon2id credential validation and login

## Task information

- Owner: Backend
- Status: Planned
- Priority: P0

## Outcome

Authenticate a user inside an organization through Argon2id verification and a uniform public login response.

## Dependencies

- BE-004
- BE-005
- BE-006

## Interfaces and source of truth

- Consumes: POST /api/v1/auth/login contract and core.resolve_login_tenant.
- Produces: user credential persistence, login application service and security audit event.

## In scope

- Migrate tenant-scoped users and profiles with composite tenant constraints and RLS policies.
- Implement Argon2id password hashing and verification.
- Require organization_slug, return a uniform failure for wrong slug, disabled tenant or wrong password, and write security audit events.

## Out of scope

- Access JWT creation, refresh cookies, RBAC and tenant middleware.

## Test-first sequence

1. Add backend/tests/api/auth/test_login.py for success, wrong password, missing slug and duplicate email across organizations.
2. Run: cd backend; python -m pytest tests/api/auth/test_login.py -q. Record the missing login-service failure.
3. Implement user persistence, password service and login use case.
4. Run the focused API test and audit/outbox integration test.

## Evidence checkpoint

- Duplicate emails across separate organizations authenticate only with the correct slug.
- Wrong slug and wrong password return the same public failure.

## Acceptance criteria

- Password plaintext is never stored, returned or logged.
- Missing or disabled slug performs dummy Argon verification.
- Login success and failure security actions are auditable without credential content.

## Reviewer checklist

- No login query bypasses the pre-login resolver boundary.
- User tenant relations use composite foreign keys and RLS in their creation migration.
