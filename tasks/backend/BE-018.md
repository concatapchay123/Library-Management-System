## Evidence checkpoint

- Expired hold advances exactly one eligible next reservation:
  Verified via `test_hold_expiry_advances_queue` in `backend/tests/unit/core/test_reservation_service.py` and `test_reservation_hold_expiry_advances_next_in_queue` in `backend/tests/integration/core/test_reservation_integration.py`. When reservation 1 expired (`hold_expires_at` past), `expire_holds` marked reservation 1 as `expired`, transitioned reservation 2 from `pending` to `held` with `hold_expires_at` set to 48 hours later and assigned the copy, while reservation 3 remained `pending` without copy allocation.
- Consumer replay cannot skip or allocate one queue entry twice:
  Verified via `test_handle_loan_returned_allocation_is_idempotent_and_safe_on_replay` in `backend/tests/unit/core/test_reservation_service.py` and `test_reservation_allocation_consumer_replay_cannot_double_allocate` in `backend/tests/integration/core/test_reservation_integration.py`. First event consumption allocated the available copy to the first eligible pending reservation and transitioned copy to `reserved`. Replay of the exact same event or duplicate copy returned `None` because the copy was already held, leaving subsequent reservations untouched and preventing double allocation or queue jumping.

## Acceptance criteria

- Queue ordering is deterministic within one copy scope:
  Queue position is calculated strictly server-side using `MAX(queue_position) + 1` within `(organization_id, book_id)`. Ordering is consistently `(queue_position ASC, created_at ASC, reservation_id ASC)`.
- Reservation mutations are tenant-scoped, authorized and audited:
  Every mutation enforces `organization_id` tenant boundaries, requires RBAC permissions (`reservation.create`, `reservation.read`, `reservation.manage`), and writes outbox and audit events (`circulation.reservation_created`, `circulation.reservation_cancelled`, `circulation.reservation_allocated`, `circulation.reservation_expired`) inside audited transactions.
- Hold expiry is durable rather than an in-memory timer:
  Hold expiration queries `core.reservations` for `status = 'held' AND hold_expires_at <= SYSUTCDATETIME()`, executing durable state transitions and outbox events in database transactions.
