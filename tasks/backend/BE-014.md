# BE-014 — Copy status transition and append-only history

## Task information

- Owner: Backend
- Status: Planned
- Priority: P1

## Outcome

Enforce physical-copy status transitions and retain an immutable actor-attributed history.

## Dependencies

- BE-013
- BE-005

## Interfaces and source of truth

- Consumes: copy persistence from BE-013 and audit transaction contract from BE-005.
- Produces: core.copy_status_history and status-transition application service.

## In scope

- Define allowed transitions among available, borrowed, lost, damaged and maintenance.
- Persist append-only history with actor, timestamp and reason.
- Make status change, history and audit record atomic.

## Out of scope

- Checkout locking, loan lifecycle, reservations and copy repair workflow.

## Test-first sequence

1. Add backend/tests/unit/core/test_copy_status.py for allowed and rejected transitions.
2. Run: cd backend; python -m pytest tests/unit/core/test_copy_status.py -q. Record the missing transition-policy failure.
3. Implement the domain policy, history migration and transactional service.
4. Run the unit test and backend/tests/integration/ops/test_audit_outbox.py.

## Evidence checkpoint

- Invalid transitions return the documented domain problem type.
- Every accepted transition has exactly one history record and one audit record.

## Acceptance criteria

- Lost, damaged and maintenance copies cannot enter a borrowable state without an explicit allowed transition.
- History rows cannot be updated or deleted through the application service.
- Status logic is copy-level, never book-level.

## Reviewer checklist

- Status and audit writes share one transaction.
- Transition reason and actor are required for manual inventory changes.
