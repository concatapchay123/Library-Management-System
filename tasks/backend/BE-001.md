# BE-001 — Backend package, app factory and health endpoints

## Task information

- Owner: Backend
- Status: Planned
- Priority: P0

## Outcome

Create a deterministic Flask package that starts through create_app(config) and exposes live and readiness health endpoints.

## Dependencies

None. Phase 0 decisions are preserved in tasks/legacy/TASK-001.md.

## Interfaces and source of truth

- Consumes: docs/architecture.md and docs/development-guide.md.
- Produces: backend/src/openlibrary/app/create_app, GET /api/v1/health/live and GET /api/v1/health/ready.

## In scope

- Add the backend package metadata, app factory, configuration object and smoke-test harness.
- Make live health independent from external services and readiness report dependency failure without secrets or stack traces.
- Define the canonical backend test, lint and type-check commands used by later backend tasks.

## Out of scope

- Database connection setup, authentication, routes other than health and Docker services.

## Test-first sequence

1. Add backend/tests/unit/app/test_factory.py covering application creation, live health and failed readiness.
2. Run: cd backend; python -m pytest tests/unit/app/test_factory.py -q. Record the missing-package failure.
3. Implement the smallest app factory and health adapters that satisfy the tests.
4. Run the focused test, then the backend commands defined by this task.

## Evidence checkpoint

- Focused app-factory test output is attached to the task record.
- The documented backend commands run without relying on an import-time network connection.

## Acceptance criteria

- create_app(config) is the sole application entry point.
- Live health returns without database or Redis access.
- Readiness uses a stable RFC Problem Details response when a dependency is unavailable.

## Reviewer checklist

- No credential, network connection or mutable global state is created during module import.
- Health responses contain no secret, stack trace or database detail.
