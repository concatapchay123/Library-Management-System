# BE-006 — OpenAPI base and backend CI quality gates

## Task information

- Owner: Backend
- Status: Planned
- Priority: P0

## Outcome

Publish the versioned API base contract and automate the backend checks needed to keep it compatible.

## Dependencies

- BE-005

## Interfaces and source of truth

- Consumes: docs/api-design.md, backend commands from BE-001 and migration controls from BE-003.
- Produces: contracts/openapi/v1.yaml, backend CI workflow and documented compatibility command.

## In scope

- Define health and authentication contract foundations, RFC Problem Details and request-correlation headers.
- Add CI jobs for backend formatting, linting, typing, unit/API tests, migration integration, OpenAPI validation and Compose validation.
- Make contract compatibility checks block unversioned breaking API changes.

## Out of scope

- Business-resource endpoint implementation, frontend client generation and release deployment.

## Test-first sequence

1. Add backend/tests/contract/test_openapi_base.py for required health, Problem Details and request-id contract elements.
2. Run: cd backend; python -m pytest tests/contract/test_openapi_base.py -q. Record the missing contract failure.
3. Implement the contract base and CI workflow.
4. Run the focused contract test and the documented OpenAPI validation command.

## Evidence checkpoint

- Contract validation output is recorded.
- CI contains a blocking job for every backend command defined by BE-001 and BE-003.

## Acceptance criteria

- API base URL is /api/v1.
- Error responses follow RFC Problem Details with a request_id.
- CI fails when backend, migration, contract or Compose checks fail.

## Reviewer checklist

- Contract changes are machine-readable and versioned.
- CI never substitutes frontend checks for backend release gates.
