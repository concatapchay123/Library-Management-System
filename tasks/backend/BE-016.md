# BE-016 — Loan request, approval, checkout and return lifecycle

## Task information

- Owner: Backend
- Status: Planned
- Priority: P1

## Outcome

Implement the core loan lifecycle with a single application service for self-service and librarian-desk flows.

## Dependencies

- BE-014
- BE-015
- BE-010

## Interfaces and source of truth

- Consumes: copy-state policy from BE-014, authorization from BE-010 and audit/outbox protocol from BE-005.
- Produces: core.loans, loan lifecycle service and documented loan endpoints.

## In scope

- Migrate loans with active-loan invariants and tenant constraints.
- Implement request, approval, direct desk checkout and return.
- Write audit and outbox records with each successful lifecycle mutation.

## Out of scope

- Concurrent checkout locking, idempotency key replay, reservation allocation, overdue jobs and edition policies.

## Test-first sequence

1. Add backend/tests/api/core/test_loans.py for request, approval, desk checkout, return and invalid state transitions.
2. Run: cd backend; python -m pytest tests/api/core/test_loans.py -q. Record the missing loan-service failure.
3. Implement the loan migration, domain transitions, service and API contract.
4. Run the focused API test and audit/outbox integration test.

## Evidence checkpoint

- Self-service requests cannot checkout without approval.
- Desk checkout invokes the same checkout service after its explicit approval action.

## Acceptance criteria

- Return changes loan and copy state atomically.
- Invalid lifecycle transitions return stable documented errors.
- All successful mutations are authorized and audited.

## Reviewer checklist

- The desk path does not bypass loan invariants.
- Payment and edition-specific conditionals do not enter core loan entities.
