# BE-002 — Backend runtime configuration and local Compose services

## Task information

- Owner: Backend
- Status: Planned
- Priority: P0

## Outcome

Provide validated local configuration and Compose services for the backend, SQL Server, Redis, worker and edge proxy.

## Dependencies

- BE-001

## Interfaces and source of truth

- Consumes: backend application configuration from BE-001 and docs/deployment.md.
- Produces: environment-variable contract, infra/docker-compose.yml health checks and local runtime commands.

## In scope

- Add names-only environment examples and strict required-setting validation.
- Define SQL Server, Redis, backend and worker service health checks with non-public database and Redis ports.
- Add local Compose configuration for backend services without SPA asset hosting.

## Out of scope

- Schema migrations, production secrets, TLS and final SPA routing.

## Test-first sequence

1. Add backend/tests/integration/app/test_runtime_config.py for absent required settings and safe defaults.
2. Run: cd backend; python -m pytest tests/integration/app/test_runtime_config.py -q. Record the validation failure.
3. Implement configuration parsing and Compose service definitions.
4. Run the focused test and docker compose -f infra/docker-compose.yml config.

## Evidence checkpoint

- Focused configuration test passes.
- Compose configuration validation output is stored with the task evidence.

## Acceptance criteria

- Missing required runtime settings fail before the server accepts requests.
- Database and Redis are not publicly exposed by default.
- Local services have explicit health checks and dependency order.

## Reviewer checklist

- No secret value is committed.
- Configuration has one documented name for each setting and no silent fallback for secret material.
