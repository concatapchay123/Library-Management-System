# BE-023 — Fine calculation, invoices and immutable allocations

## Task information

- Owner: Backend
- Status: Planned
- Priority: P2

## Outcome

Assess public-library fines and issue immutable invoices with allocation rules that preserve financial integrity.

## Dependencies

- BE-022
- BE-005

## Interfaces and source of truth

- Consumes: member/subscription records from BE-022 and audit/outbox transaction contract from BE-005.
- Produces: fines, invoices, invoice lines and allocation service using decimal money values.

## In scope

- Migrate fines, invoices, invoice lines and allocation records with explicit currency and decimal(19,4) values.
- Implement fine assessment and immutable issued invoices.
- Enforce allocation totals that cannot exceed their related fine or payment amount.

## Out of scope

- Payment-provider callbacks, reconciliation, general ledger and frontend payment entry.

## Test-first sequence

1. Add backend/tests/integration/public_library/test_fines_invoices.py for money precision, invoice immutability and allocation caps.
2. Run: cd backend; python -m pytest tests/integration/public_library/test_fines_invoices.py -q. Record the missing finance-service failure.
3. Implement migrations, money value types, services, contracts and API adapters.
4. Run the focused integration test and audit/outbox test.

## Evidence checkpoint

- Issued invoice lines and totals cannot be changed.
- Over-allocation and floating-point money paths are rejected.

## Acceptance criteria

- Currency is explicit for every money amount.
- Financial transitions are auditable and tenant isolated.
- Fine calculation is independent from a browser or payment provider callback.

## Reviewer checklist

- Decimal arithmetic is used end to end.
- No general accounting ledger is added.
