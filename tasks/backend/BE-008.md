# BE-008 — Access JWT verification and protected principal

## Task information

- Owner: Backend
- Status: Completed
- Priority: P0

## Outcome

Issue and verify short-lived access JWTs, then expose one protected principal to application services.

## Dependencies

- BE-007

## Interfaces and source of truth

- Consumes: authenticated login result from BE-007 and docs/security.md.
- Produces: JWT issuer, verifier, protected-request principal and GET /api/v1/auth/me.

## In scope

- Issue short-lived access tokens after login.
- Verify RS256 algorithm, issuer, audience, expiration and kid before building a principal.
- Restrict principal contents to user, organization, session and effective authorization identifiers.

## Out of scope

- Refresh rotation, CSRF validation, role assignment and browser routing.

## Test-first sequence

1. Add backend/tests/api/auth/test_access_tokens.py for issuer, audience, algorithm, expiry and unknown-kid rejection.
2. Run: cd backend; python -m pytest tests/api/auth/test_access_tokens.py -q. Record the missing verifier failure.
3. Implement token issuance, key lookup and protected principal middleware.
4. Run the focused API test.
