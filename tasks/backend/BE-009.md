# BE-009 — Refresh-session rotation, revoke and CSRF boundary

## Task information

- Owner: Backend
- Status: Completed
- Priority: P0

## Outcome

Implement secure browser refresh sessions with single-use rotation, chain revocation and CSRF-protected mutation endpoints.

## Dependencies

- BE-008

## Interfaces and source of truth

- Consumes: protected principal and token settings from BE-008.
- Produces: core.refresh_sessions, refresh resolver, refresh/logout endpoints and cookie/CSRF contract.

## In scope

- Store only refresh-token hashes with parent-chain and revocation metadata.
- Rotate a valid refresh token once, revoke the chain on reuse and reject revoked sessions.
- Use Secure HttpOnly cookie delivery and CSRF verification for refresh/logout mutations.

## Out of scope

- Password reset, social login, frontend session state and RBAC administration.

## Test-first sequence

1. Add backend/tests/api/auth/test_refresh_sessions.py for rotation, reuse, logout, invalid token and missing CSRF.
2. Run: cd backend; python -m pytest tests/api/auth/test_refresh_sessions.py -q. Record the missing refresh-session failure.
3. Implement the migration, resolver, services and API endpoints.
4. Run the focused API test and the tenancy resolver integration test.

## Evidence checkpoint

- Reusing a rotated token revokes its chain.
- Invalid or revoked hashes cannot resolve tenant context.

## Acceptance criteria

- Refresh plaintext never enters database, logs, audit payloads or API responses.
- Logout revokes the active chain.
- Refresh and logout reject missing or invalid CSRF state.
