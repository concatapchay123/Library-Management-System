# BE-005 — Audit and outbox transactional persistence

## Task information

- Owner: Backend
- Status: Completed
- Priority: P0

## Outcome

Provide immutable audit and durable outbox records that share a transaction boundary with protected mutations.

## Dependencies

- BE-004

## Interfaces and source of truth

- Consumes: docs/system-design.md, docs/database-design.md and the tenant predicate from BE-004.
- Produces: ops.audit_events, ops.outbox_events and the application transaction contract for audited asynchronous effects.

## In scope

- Migrate tenant-scoped audit and outbox tables with payload version, correlation id and server-derived tenant context.
- Add application persistence ports that write domain mutation, audit event and outbox event atomically.
- Enforce secret and raw-token exclusion from audit and outbox payloads.

## Out of scope

- Event claiming, worker retry, email delivery and notification views.

## Test-first sequence

1. Add backend/tests/integration/ops/test_audit_outbox.py for atomic commit and rollback behavior.
2. Run: cd backend; python -m pytest tests/integration/ops/test_audit_outbox.py -q. Record the absent transactional record failure.
3. Implement the migrations and persistence ports.
4. Run the focused test against SQL Server.

## Evidence checkpoint

- A successful mutation has both required records in one transaction.
- A rolled-back mutation leaves neither record.

## Acceptance criteria

- Audit records are append-only.
- Outbox records carry a versioned event type and server-created organization context.
- Sensitive credentials, tokens and raw payment payloads are rejected from persistent event data.

## Reviewer checklist

- No best-effort audit write exists outside the mutation transaction.
- Tenant ownership and RLS protection apply to both tables.
