# BE-004 — Organization registry, RLS predicate and pre-login tenant resolver

## Task information

- Owner: Backend
- Status: Planned
- Priority: P0

## Outcome

Create the fail-closed organization registry and the narrow database boundary required to resolve a login tenant before authenticated context exists.

## Dependencies

- BE-003

## Interfaces and source of truth

- Consumes: docs/foundational-decisions.md, docs/database-design.md and docs/security.md.
- Produces: core.organizations, shared RLS predicate and core.resolve_login_tenant.

## In scope

- Migrate the RLS-protected organization root registry.
- Add the shared tenant predicate with both filter and block behavior.
- Implement the narrowly granted security-definer login resolver and deny direct pre-context registry reads.

## Out of scope

- Password verification, public organization administration, tenant middleware and refresh-session lookup.

## Test-first sequence

1. Add backend/tests/integration/tenancy/test_prelogin_resolver.py for missing context denial and resolver-only tenant discovery.
2. Run: cd backend; python -m pytest tests/integration/tenancy/test_prelogin_resolver.py -q. Record the missing RLS boundary failure.
3. Implement the registry migration, RLS predicate and resolver.
4. Run the focused test and the migration catalog check.

## Evidence checkpoint

- Missing tenant context is denied for organization rows.
- The resolver is the only pre-context path granted tenant discovery.

## Acceptance criteria

- Organization data is RLS-protected despite being the tenant root.
- A caller cannot turn a client-supplied organization id into an authorized context.
- Resolver output contains only the fields needed by the login service.

## Reviewer checklist

- Filter and block predicates are both present.
- Resolver grants are narrow and no direct table read bypass is introduced.
