# BE-024 — Signed payment webhook, reconciliation and payment idempotency

## Task information

- Owner: Backend
- Status: Completed
- Priority: P2

## Outcome

Safely accept provider payment events, reconcile pending payments and prevent duplicate settlement.

## Dependencies

- BE-023
- BE-015

## Interfaces and source of truth

- Consumes: financial records from BE-023, worker protocol from BE-015 and webhook rules in docs/security.md.
- Produces: payment state machine, provider-event deduplication, raw-body signature verifier and reconciliation consumer.

## In scope

- Verify provider signature and replay timestamp on raw request body before parsing or state mutation.
- Persist provider event identity and idempotent payment references.
- Reconcile pending payments through durable outbox work and support documented partial/refund allocation states.

## Out of scope

- Storing card data, provider credentials in database, frontend checkout widgets and a general ledger.

## Test-first sequence

1. Add backend/tests/integration/public_library/test_payments.py for invalid signature, stale replay, duplicate event, timeout reconciliation and refund allocation.
2. Run: cd backend; python -m pytest tests/integration/public_library/test_payments.py -q. Record the missing payment-boundary failure.
3. Implement verifier, payment state machine, deduplication, reconciliation and API contract.
4. Run the focused integration test and dispatcher replay test.
